PHÉNIX 360 est le poste de pilotage d'un conducteur de travaux, doublé d'un espace client simple et rassurant. Un seul principe fondateur : le Journal est la source de vérité, tout le reste n'en est qu'une lecture. Ce document présente chaque brique, comment elles se parlent, ce que chacun voit, et où va le produit.

04 — Modèles de données

Les objets, simplement

Sans code : juste ce qui contient quoi. Deux familles cohabitent — l'Événement (le Journal) et le Moment (Le Fil) — reliées par des références, jamais par des copies.

L'Événement — le Journal

Event enveloppe commune + auteur, date, visibilité, statut
type compte-rendu · photo · document
demande question → réponse
decision choix client (envoyée, validée…)
reserve n°, libellé, responsable, échéance
levee preuve, note → pointe vers la réserve

Le Moment — Le Fil

Moment un instant partagé + zone, couverture
photos[] une ou plusieurs (album)
annotations[] calque sur la photo
action → crée une réserve (Journal)
messages[] « un petit mot »

La Bibliothèque n'est pas un objet : c'est la liste des photos de tous les Moments, à plat. « 1 partage = 2 vues ».

07 — Sources de vérité

D'où vient chaque information

Une règle d'or : on ne stocke jamais deux fois la même chose. Un statut n'est pas enregistré, il est calculé à la lecture.

Le Journal

La source unique. Toutes les vues lisent ici. On ajoute, on n'efface pas (append-only).

Une Réserve

Vit dans le Journal, comme un événement. Sa vue dédiée n'est qu'une lecture filtrée.

Le statut « levée »

Jamais stocké. Calculé : une réserve est « levée » s'il existe un événement de levée qui la vise.

L'avancement

Déduit du dernier compte-rendu confirmé. Aucun pourcentage saisi à la main.

Le Fil

Agrégat distinct du Journal (l'espace de vie photo), persisté à part, relié par références.

La visibilité client

Une seule règle décide de ce que le client voit. Les vues n'improvisent jamais.
